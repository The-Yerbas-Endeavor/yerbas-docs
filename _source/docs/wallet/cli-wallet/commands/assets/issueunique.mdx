# issueunique

RPC help captured from **Yerbas Core 4.0.1.4** (`f0e2dde`).

Use `./yerbas-cli help issueunique` on your node for help. In the GUI console omit `yerbas-cli`. HTTP examples use mainnet RPC port 15419; network-specific defaults and availability can differ.

```text
issueunique "root_name" [asset_tags] ( [ipfs_hashes] ) "( to_address )" "( change_address )"

THIS COMMAND IS NOT YET ACTIVE!
https://github.com/The-Yerbas-Endeavor/yerbas

V4 mainnet wallet policy: asset creation, sending, reissuance, ownership transfers, and asset reward payouts
are locked below tip height 1195400. Receiving/viewing assets and ordinary YERB payments remain available.
Testnet/regtest are unaffected. This is wallet policy, not a consensus restriction on raw transactions.

Issue unique asset(s).
root_name must be an asset you own.
An asset will be created for each element of asset_tags.
If provided ipfs_hashes must be the same length as asset_tags.
Five (5) YERB will be burned for each asset created.

Arguments:
1. "root_name"             (string, required) name of the asset the unique asset(s) are being issued under
2. "asset_tags"            (array, required) the unique tag for each asset which is to be issued
3. "ipfs_hashes"           (array, optional) ipfs hashes or txid hashes corresponding to each supplied tag (should be same size as "asset_tags")
4. "to_address"            (string, optional, default=""), address assets will be sent to, if it is empty, address will be generated for you
5. "change_address"        (string, optional, default=""), address the the yerb change will be sent to, if it is empty, change address will be generated for you

Result:
"txid"                     (string) The transaction id

Examples:
> yerbas-cli issueunique "MY_ASSET" '["primo","secundo"]'
> yerbas-cli issueunique "MY_ASSET" '["primo","secundo"]' '["first_hash","second_hash"]'
```
